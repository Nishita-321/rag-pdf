# Step 3: the web app (FastAPI)

The pipeline is now usable from a browser: upload PDFs, pick one (or all), ask questions, see the answer with its source chunks.

## Run

```bash
source .venv/bin/activate
uvicorn app:app --reload
```

| URL | What |
|-----|------|
| http://localhost:8000 | The web page |
| http://localhost:8000/docs | Interactive API docs (generated by FastAPI) |

`--reload` restarts the server when you edit code. Leave it off in production.

## Files

| File | Role |
|------|------|
| `app.py` | FastAPI server: HTTP in, calls `rag.py`, JSON out |
| `rag.py` | The pipeline. No web code in it |
| `static/index.html` | The whole web page: HTML, CSS and JavaScript in one file |
| `config.py` | Settings, now including `MAX_UPLOAD_MB` |

The split matters: `rag.py` knows nothing about HTTP, and `app.py` knows nothing about embeddings. The terminal version (`python rag.py file.pdf`) uses the same functions and still works.

## Request flow

```
Upload:  browser -> POST /documents -> rag.index_document -> ChromaDB
Ask:     browser -> POST /ask -> rag.answer -> ChromaDB search -> Gemini -> browser
```

## API

| Method | Path | Body | Returns |
|--------|------|------|---------|
| `GET` | `/` | | The web page |
| `GET` | `/health` | | `{"status": "ok", "llm_model": ..., "gemini_key_set": true}` |
| `GET` | `/metrics` | | Prometheus metrics, see [07-monitoring.md](07-monitoring.md) |
| `POST` | `/documents` | Form field `file` (a PDF) | `201` and the document |
| `GET` | `/documents` | | List of documents |
| `DELETE` | `/documents/{doc_id}` | | `204` |
| `POST` | `/ask` | `{"question": "...", "doc_id": "..."}` | `{"answer": "...", "sources": [...]}` |

`doc_id` in `/ask` is optional. Leave it out to search all documents.

A document looks like:

```json
{"doc_id": "1349f8a4a041ff2f", "name": "test.pdf", "pages": 2, "chunks": 5}
```

A source looks like:

```json
{"doc_id": "1349f8a4a041ff2f", "name": "test.pdf", "page": 2, "text": "the chunk text..."}
```

### Errors

Every error is JSON: `{"detail": "message"}`.

| Status | When |
|--------|------|
| `400` | Not a PDF, PDF has no text, nothing indexed yet, Gemini key missing |
| `404` | Deleting a document that does not exist |
| `413` | PDF larger than `MAX_UPLOAD_MB` (default 20) |
| `422` | Request body is malformed, e.g. empty question |
| `502` | Gemini itself failed (bad key, rate limit, wrong model name) |

### Try it with curl

```bash
curl -F "file=@pdfs/test.pdf" localhost:8000/documents
curl localhost:8000/documents
curl -X POST localhost:8000/ask -H "Content-Type: application/json" \
     -d '{"question": "What is this document about?"}'
```

## What changed in `rag.py`

Supporting several documents needed three fixes to the original script.

| Before | Now |
|--------|-----|
| Id was the file path as typed | Id is a hash of the file's contents. Same file = same id, whatever its name |
| Search covered every PDF ever indexed | `retrieve` and `answer` take a `doc_id` and search only that document |
| Re-indexing could leave stale chunks | Old chunks for that id are deleted before the new ones are added |
| `sys.exit` on problems | Raises `RagError`, which `app.py` turns into a `400` |
| Took a file path | Takes the file's bytes, so uploads never need to be saved to disk |

New functions: `list_documents()` and `delete_document(doc_id)`.

## Design decisions

- **Uploaded PDFs are not kept.** Only the chunks and vectors are stored in ChromaDB. Less to store and secure, but to re-index with new chunk settings you must upload again.
- **Uploading the same file twice replaces it** instead of duplicating it. The name shown is the most recent one.
- **Routes are `def`, not `async def`.** Embedding and the Gemini call block. FastAPI runs `def` routes in a thread pool, so a slow request does not freeze the others.
- **The embedding model loads once at startup**, which is why the server takes a few seconds to start.
- **Each question is independent.** The page shows a chat history, but earlier questions are not sent to Gemini. "What about the second one?" will not work.
- **The page inserts text with `textContent`**, never as HTML, so text inside a PDF cannot inject markup.

## Limits

| Limit | Effect |
|-------|--------|
| No login | Anyone who can reach the server can upload, ask and delete. Fine on `localhost`, not on the internet |
| Indexing happens inside the upload request | A very large PDF makes the upload wait until embedding finishes |
| One server process only | The on-disk ChromaDB cannot be shared by several processes |
| No streaming | The answer appears all at once |
